5. DEFECTOS ENCONTRADOS Y CORREGIDOS EN ESTE BLOQUE

  D1. Sandbox y vista productiva usaban componentes distintos
      (DiagBadge, banner y unclosed card duplicados). El sandbox no
      verificaba los componentes reales. → Extracción a _components/,
      importados por ambos.

  D2. Fixture "complete" declaraba mappings de 5 categorías pero solo
      aportaba datos de food+liquor, generando 12 incidencias falsas
      (Beer/Wine/NA Beverage con "falta cuenta" + "teórico incompleto").
      → Mappings reducidos a las categorías que el fixture realmente
      alimenta; MAPPINGS_FULL sigue disponible para escenarios que sí
      necesitan las cinco categorías.

  D3. La ruta sandbox devolvía HTTP 200 en producción a pesar de
      llamar notFound() en el server component. Reproducido con curl
      contra `next start` (NODE_ENV=production confirmado por log
      temporal): el cuerpo era la página not-found pero el status
      HTTP quedaba 200 — sospechado edge-case de App Router cuando el
      layout ancestro es un client component ("use client" en
      /dashboard/layout.tsx).
      → Fix en src/proxy.ts: gate temprano
        if (process.env.NODE_ENV === 'production' &&
            request.nextUrl.pathname.startsWith('/dashboard/costo-uso/sandbox/'))
          return new NextResponse('Not Found', { status: 404 })
      Se añadieron además not-found.tsx en el segmento sandbox y en
      [scenario] como boundary explícito. El log temporal se quitó.
      Verificado con curl tras next build && next start: 404 para las
      3 URLs sandbox probadas y 200 para /dashboard y
      /dashboard/costo-uso.
